## 四、播放链路完整流程

```
用户双击歌曲
  ↓
handlePlay(song) → invoke("play_url", {song_id: "kugou:hash:audio_id"})
  ↓
play.rs 解析 song_id → 拆出 hash + audio_id
  ↓
kugou_sidecar::song_url(hash, 0, token, userid, dfid)
  ↓
sidecar_get("http://127.0.0.1:6521/song/url?hash=xxx&album_audio_id=0&...")
  ↓
返回 URL → audio::play_url(url)
  ↓
rodio 下载 + 解码 + 播放
  ↓
前端轮询 audio_state 更新进度条
```

## 七、后续加功能的正确姿势

### ⚠️ 黄金法则（2026-08-05 血泪教训）

**只要出现「不相关改动却坏了」的情况 → 立刻回滚 → 拆零件 → 重新加零件**

### 错误示范（加托盘搞坏收藏和搜索）

```rust
// ❌ 错误：托盘代码直接塞进 lib.rs 的 setup
.invoke_handler([...])
.setup(|app| {
    // 托盘代码 50 行
    TrayIconBuilder::new()...
    // 和登录态初始化抢执行顺序
})
.on_window_event(|window, event| {
    // 又塞窗口事件处理
})
.run(...)
```

**问题**：`lib.rs` 是总装车间，不是零件。托盘代码直接塞进去，影响其他初始化流程。

### 正确姿势（零件化）

```
src-tauri/src/
├── tray.rs              ← 托盘零件（独立文件）
│   ├── init_tray()      ← 初始化托盘
│   └── on_menu_event()  ← 菜单事件处理
│
├── lib.rs               ← 总装（只负责调用）
│   └── .setup(|app| {
│           tray::init_tray(app)?;  // 一行调用
│           // 其他初始化...
│       })
```

### 零件拆分四原则

| 原则 | 说明 | 反例（❌） | 正例（✅）
|------|------|-----------|----------
| **一个零件 = 一个文件** | 托盘、窗口、歌词各自独立文件 | 托盘代码塞 lib.rs | `tray.rs` 独立文件 |
| **零件只做一件事** | 托盘只管托盘，不管窗口事件 | 托盘 + 窗口事件混一起 | 托盘只管图标和菜单 |
| **零件不抢执行顺序** | 每个 init 函数独立，互不影响 | setup 里顺序敏感 | 每个 init 幂等 |
| **总装只负责调用** | lib.rs 只写一行 `xxx::init()` | lib.rs 里写 100 行逻辑 | lib.rs 只调用 init |

### 加功能标准流程

```
1. 写零件（独立文件）
   ↓
2. 在 lib.rs 里加一行调用
   ↓
3. 编译测试
   ↓
4. 测试播放功能（必须测！）
   ↓
5. 坏了 → 立刻回滚 → 检查零件是否独立
   ↓
6. 没坏 → 继续
```
